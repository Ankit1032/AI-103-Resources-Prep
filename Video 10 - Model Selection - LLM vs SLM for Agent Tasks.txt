### Unit 5 Introduction – Choosing the Right Brain for Your Agent

Unit 4 covered safety controls. Unit 5 covers model selection – choosing which AI model powers your agent's reasoning.

• Review of Unit 4: You learned to filter harmful content and run red teaming tests. Now you need to choose the model that your agent uses as its brain.

• What This Unit Covers: You will learn the difference between Large Language Models (LLMs) and Small Language Models (SLMs), when to use each, and how to deploy them in Foundry.

• Why Model Selection Matters: The wrong model costs too much, responds too slowly, or lacks capability for your agent's tasks.

Exam Takeaway: Model selection is part of the Generative AI domain (20% weighting). The exam tests your ability to match model types to agent tasks.


### What Is a Large Language Model (LLM)?

A Large Language Model (LLM) is a very large AI model with billions of parameters, trained on massive amounts of text from the internet and books.

• LLM Size Definition: An LLM has over 10 billion parameters (internal settings learned during training). GPT-4o has over 1 trillion parameters.

• LLM Capabilities: LLMs excel at complex reasoning, following nuanced instructions, understanding context, and generating creative responses.

• LLM Cost and Speed: LLMs are expensive to run (higher cost per token) and slower to respond (higher latency in milliseconds) than smaller models.

Exam Takeaway: LLMs are large, capable, expensive, and slow. Use them when you need complex reasoning, not for simple tasks.


### What Is a Small Language Model (SLM)?

A Small Language Model (SLM) is a compact AI model with fewer than 10 billion parameters, designed for speed and low cost on specific tasks.

• SLM Size Definition: SLMs typically have 1 billion to 7 billion parameters. Microsoft Phi-3 mini has 3.8 billion parameters.

• SLM Capabilities: SLMs excel at specific tasks like classification, summarization, entity extraction, and simple question answering.

• SLM Cost and Speed: SLMs are cheap to run (lower cost per token) and very fast (low latency in milliseconds), making them ideal for high-volume tasks.

Exam Takeaway: SLMs are small, fast, cheap, and good at specific tasks. Use them for high-volume, narrow-scope agent operations.


### GPT-5: The New Standard for Frontier Intelligence

GPT-5.5 is OpenAI's most capable model available in Foundry, designed for complex reasoning, multimodal understanding, and agent orchestration.

• GPT-5.5 Capabilities: GPT-5.5 can process text, images, and audio simultaneously. It excels at multi-step reasoning, tool calling, and following complex system instructions.

• GPT-5.5 Token Limit: GPT-5.5 supports 1,000,000 tokens of context. This allows the agent to remember very long conversations or process large documents.

• When to Use GPT-5.5: Use GPT-5.5 as the manager agent in multi-agent systems, for complex planning tasks, or when you need the highest accuracy.

Exam Takeaway: GPT-5.5 is the most capable model. Use it for agent managers, complex reasoning, and tasks requiring multimodal input.


### Phi-3 and Phi-4 – Microsoft's SLM Family

Phi-3 and Phi-4 are Microsoft's small language models, optimized for fast, cheap inference on specific agent tasks like summarization and classification.

• Phi Model Sizes: Phi-3 comes in mini (3.8B parameters), small (7B), and medium (14B). Phi-4 adds improved reasoning in a compact 14B size.

• Phi Training Data: Phi models are trained on high-quality synthetic data and filtered web content, not raw internet dumps. This makes them more efficient.

• When to Use Phi Models: Use Phi models for high-volume classification, sentiment analysis, entity extraction, or summarization where GPT-4o is overkill.

Exam Takeaway: Phi models are Microsoft's SLMs. Use them for narrow, high-volume tasks where cost and speed matter more than maximum capability.


### Matching Model to Agent Task – Reasoning vs. Summarization

Different agent tasks require different model capabilities. Choose an LLM for reasoning tasks and an SLM for summarization or classification tasks.

• Reasoning Task Example: An agent that plans a vacation itinerary with flights, hotels, and activities needs complex reasoning. Use GPT-5.5.

• Summarization Task Example: An agent that summarizes 10,000 customer reviews per hour needs speed and low cost. Use Phi-3 mini.

• Classification Task Example: An agent that categorizes support tickets into 20 types needs fast, cheap inference. Use Phi-3 small.

Exam Takeaway: The exam presents agent task descriptions. You must match the task to the correct model type – LLM for reasoning, SLM for summarization/classification.


### Deploying a Model in Foundry Model Catalog

Deploying a model in Foundry means reserving a dedicated copy of that model, with its own endpoint URL and API keys, for your agent to use.

• Deployment Steps: In Foundry Model Catalog, select a model (GPT-5.5, Phi-3). Choose a deployment name, capacity (tokens per minute), and region.

• Deployment Capacity: Capacity determines how many tokens per minute your agent can process. Higher capacity costs more but handles higher traffic.

• Deployment Lifecycle: Deployed models can be updated (new version), scaled (increase capacity), or deleted (stop paying). Each deployment has its own endpoint.

Exam Takeaway: Deploying creates a dedicated model endpoint. Capacity controls throughput. Know the difference between deployment (reserving) and inference (calling).


### Model Endpoints – How Your Agent Calls the Model

When you deploy a model, Foundry gives you an endpoint URL that your agent code calls to send prompts and receive responses.

• Endpoint URL Format: The URL looks like
`https://your-project.foundry.azure.com/models/gpt-5/deployments/my-deployment/chat/completions`.

• API Key Authentication: Each deployed model endpoint has its own API key. Your agent includes this key in the `api-key` header of every request.

• Agent Reference: In your agent code, you configure which model endpoint to use. An agent can switch between models by changing the endpoint URL.

Exam Takeaway: Each deployed model has a unique endpoint URL and API key. Your agent code references these to call the model.
```


### Model Capacity and Quotas

Model capacity is measured in tokens per minute (TPM). Quotas limit how many tokens your agent can process across all deployed models.

• Tokens Per Minute (TPM) Definition: TPM is the maximum number of tokens your agent can send and receive in one minute. 10,000 TPM handles moderate traffic.

• Regional Quotas: Each Azure region has a global quota for each model. You may need to request a quota increase from Microsoft for high-volume agents.

• Monitoring Usage: Foundry shows your TPM usage in metrics. If you exceed quota, the model returns a 429 error (Too Many Requests) until the next minute.

Exam Takeaway: TPM quotas limit throughput. Exceeding quota causes 429 errors. Monitor usage and request quota increases for production agents.
```


### Cost Optimization – When to Use SLMs

SLMs like Phi-3 cost 10 to 50 times less per token than LLMs like GPT-5.5, making them essential for high-volume agent tasks.

• Cost per Token Comparison: GPT-5.5 costs approximately $0.01 per 1,000 input tokens. Phi-3 mini costs approximately $0.0002 per 1,000 tokens.

• Volume Math: A customer service agent handling 1 million tokens per day costs $10/day with GPT-5.5 but only $0.20/day with Phi-3 mini.

• Hybrid Approach: Use GPT-5.5 for complex reasoning steps. Use Phi-3 for simple classification, extraction, or routing within the same agent workflow.

Exam Takeaway: SLMs are dramatically cheaper than LLMs. The exam expects you to choose SLMs for high-volume, narrow-scope tasks to control costs.
```


### Latency Considerations for Agent Responsiveness

Latency is the time between sending a prompt and receiving a response. SLMs respond faster than LLMs, which matters for real-time agent interactions.

• Latency Numbers: GPT-5.5 typically responds in 500–2000 milliseconds. Phi-3 mini typically responds in 50–200 milliseconds.

• User Experience Impact: A 2-second delay feels natural. A 2-second delay for each of 10 agent steps (20 seconds total) feels broken.

• Reducing Latency: Use SLMs for fast sub-agents. Use LLMs only for the manager agent that coordinates others. Cache repeated responses.

Exam Takeaway: Latency adds up across multi-step agents. The exam tests your ability to choose faster SLMs for high-frequency agent actions.
```


### Multi-Model Agents – Using Different Models for Different Steps

A single agent can use multiple models—an SLM for fast classification, then an LLM for complex reasoning only when needed.

• Routing Pattern: User input first goes to Phi-3 for intent classification. If the intent is simple (e.g., "check balance"), Phi-3 responds directly.

• Escalation Pattern: If the intent is complex (e.g., "plan a dispute resolution strategy"), the agent calls GPT-5.5 for deeper reasoning.

• Cost Savings: Around 90% of requests route to the inexpensive Phi-3 model. Only about 10% escalate to GPT-5.5, dramatically reducing overall cost.

Exam Takeaway: Multi-model agents optimize both cost and latency. Route simple tasks to SLMs and escalate complex tasks to LLMs. This routing pattern is frequently tested in the exam.
```


### System Instructions – Model-Specific Considerations

System instructions (persistent behavior rules) must be written differently for SLMs vs. LLMs because SLMs follow instructions less reliably on complex rules.

• LLM System Instructions: GPT-5.5 handles long, complex instructions with conditional logic. Example: "If user asks about a refund, check the order date first. If the order is under 30 days, approve."

• SLM System Instructions: Phi-3 works best with short, direct instructions. Example: "Classify support tickets into one of these categories: Billing, Technical, or Account."

• Testing Required: Always test system instructions with your chosen model. An instruction that works well with GPT-5.5 may fail on Phi-3 because of its smaller size and more limited reasoning capabilities.

Exam Takeaway: SLMs require shorter and simpler system instructions. LLMs can reliably follow complex conditional logic. The exam tests your ability to match instruction complexity to model capability.
```


### Coding Pattern – Calling a Deployed Model Endpoint

Your agent code calls a deployed model endpoint using either the Azure AI Inference SDK or a direct REST API with a JSON request body.

• SDK Pattern: Use `from azure.ai.inference import ChatCompletionsClient`. Create the client with the endpoint and key. Call `client.complete()` with a messages list.

• REST Pattern: Send a POST request to:
`https://endpoint/openai/deployments/deployment-name/chat/completions?api-version=2025-01-01`
The request body includes a `messages` array containing the system and user messages.

• Response Handling: Both the SDK and REST API return a JSON response. Extract the assistant's reply from `choices[0].message.content`.

Exam Takeaway: The exam tests both SDK and REST patterns for calling deployed models. Know how to construct the JSON `messages` array.
```


### Streaming Responses vs. Batched Responses

Streaming sends model responses token by token as they are generated. Batched responses wait for the complete response before sending.

• Streaming Definition: With `stream: true`, the model sends tokens one at a time as they are generated. Your agent can display partial responses to users immediately.

• Batched Definition: With `stream: false` (default), the model generates the complete response before sending it. Users wait longer but receive the entire response at once.

• When to Stream:
  - Use **streaming** for chat agents and conversational interfaces where responsiveness improves user experience.
  - Use **batched responses** for background processing, document generation, or when your application needs the complete response before parsing or processing it.

Exam Takeaway: Streaming improves perceived speed and user experience for chat applications. Batched responses are simpler for parsing and backend workflows. The exam tests when each approach is appropriate.
```


### Unit 5 Summary – Model Selection for Agents

You have learned to choose between LLMs and SLMs based on task complexity, cost, latency, and volume requirements.

• LLMs (GPT-5.5): Large, capable, expensive, and slower. Use for complex reasoning, multi-step planning, and as manager agents in multi-agent systems.

• SLMs (Phi-3/Phi-4): Small, focused, inexpensive, and fast. Use for high-volume classification, summarization, entity extraction, and routing tasks.

• Multi-Model Pattern: Route simple tasks to SLMs. Escalate complex tasks to LLMs. This optimizes cost while maintaining capability.

• Next Unit Preview: Unit 6 introduces Agentic RAG—dynamic retrieval where agents decide when and how to search for grounding information.

Exam Takeaway: Master the tradeoffs between LLMs and SLMs, and the multi-model routing pattern for cost optimization.
